# Multi Persona — AI Interview Panel

[![Build](https://github.com/AgoraIO-Conversational-AI/agent-quickstart-nextjs/actions/workflows/build-check.yml/badge.svg)](https://github.com/AgoraIO-Conversational-AI/agent-quickstart-nextjs/actions/workflows/build-check.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)
[![Node](https://img.shields.io/badge/node-%3E%3D22-brightgreen)](https://nodejs.org/)

Multi Persona runs live, voice-based interview panels: a recruiter configures a role, focus areas, a panel of AI interviewer personas (Technical / Product / Behavioral), a per-persona time budget, and their own email, then shares a candidate link. The candidate does a mic check and talks with the panel over a real-time voice call; each persona auto-hands off to the next when its time budget expires, with full context carried forward, and the interview ends automatically once the last persona's time is up (or earlier, if the candidate ends it). The candidate gets an instant feedback report in-browser, and the recruiter gets the same report by email.

It's built on the [Agora Conversational AI Engine](https://docs.agora.io/en/conversational-ai) and Next.js — voice agent visualizer ([Agent UIKit](https://agoraio-conversational-ai.github.io/agent-uikit/)), live transcript, and real-time pipeline latency via `AGENT_METRICS` ([Agent Toolkit](https://github.com/AgoraIO-Conversational-AI/agent-client-toolkit-ts)) all come from the underlying Agora quickstart recipe this app extends.

## Prerequisites

- [Node.js 22+](https://nodejs.org/en/download/)
- [pnpm](https://pnpm.io/installation)
- [Agora CLI](https://github.com/AgoraIO-Community/cli)
- A Postgres database (e.g. [Neon](https://neon.tech)) for session/report storage

## Run It

1. **Install the Agora CLI and sign in**
   _(skip if `agora` is already on your PATH)_:

   macOS and Linux:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/AgoraIO/cli/main/install.sh | sh -s -- --add-to-path
   ```

   Windows PowerShell:

   ```powershell
   irm https://dl.agora.io/cli/install.ps1 | iex
   ```

   If the Windows install command fails in PowerShell, try running the macOS/Linux command from [Git Bash](https://git-scm.com/downloads/win), then open a new terminal and run `agora --help` to confirm the CLI is on your PATH.

   Then verify and sign in:

   ```bash
   agora --help
   agora login
   ```

   If `agora --help` is not found after install, close and reopen your terminal, then try again. If it still fails, check that the installer-added Agora CLI location is on your shell `PATH`.

2. **Install dependencies and wire credentials**

   ```bash
   pnpm install
   agora project use <your-project>
   agora project env write .env.local
   ```

   Then add `DATABASE_URL` (a pooled Postgres connection string) to `.env.local` — see [`env.local.example`](env.local.example).

3. **Push the schema and run**

   ```bash
   pnpm run db:push
   pnpm dev
   ```

4. Open [http://localhost:3000](http://localhost:3000), fill out the role/persona setup form, and open the generated candidate link in a second tab (or share it) to join as the candidate.

If the agent does not join or transcripts do not appear, run **`agora project doctor --deep`** to check credentials, feature enablement, network reachability, and local env binding.

### Deploy to Vercel

Set the environment variables below in Vercel Project Settings → Environment Variables (including `DATABASE_URL` pointed at your hosted Postgres instance), then deploy as a standard Next.js app.

### Environment variables

Defined in [`env.local.example`](env.local.example).

| Variable                     | Required | Notes                                                            |
| ----------------------------- | :------: | ------------------------------------------------------------------ |
| `NEXT_PUBLIC_AGORA_APP_ID`   |    ✅    | Agora Console → Project → App ID.                                |
| `NEXT_AGORA_APP_CERTIFICATE` |    ✅    | Agora Console → Project → App Certificate. **Server-side only.** |
| `DATABASE_URL`               |    ✅    | Pooled Postgres connection string (e.g. Neon). Required at import time by `lib/db` — every `/api/session*` route depends on it. |
| `NEXT_LLM_API_KEY` / `NEXT_LLM_URL` |    | Optional. When both are set, the end-of-interview feedback report is generated by an LLM instead of the deterministic heuristic builder. |
| `GROQ_API_KEY`                |          | Optional. When set, Groq (`openai/gpt-oss-20b` via the OpenAI SDK) summarizes persona hand-off context and is tried before `NEXT_LLM_API_KEY` for feedback report generation. Falls back to existing behavior if unset. |
| `EMAIL_HOST_USER` / `EMAIL_HOST_PASSWORD` |    | Optional. Gmail SMTP credentials used by `lib/mailer.ts` to email the recruiter their detailed report after an interview ends. When unset, reports are still generated and shown to the candidate, just not emailed. |

The default agent configuration in [`app/api/invite-agent/route.ts`](app/api/invite-agent/route.ts) uses Agora-managed STT, LLM, and TTS, so no extra vendor API keys are required beyond the three required variables above.

## Architecture

The browser fetches a combined RTC + RTM token (`buildTokenWithRtm`) from this app, joins the channel using a single RTC client, and uses RTM as the data channel for transcript, agent state, metrics, and error events. The Conversational AI Engine joins the same channel as a fixed agent UID (`lib/agora.ts`) that never varies by persona — a persona switch is a stop-and-restart of that one agent session, not a second agent joining. See [docs/ai/L1/L2/persona_handoff.md](docs/ai/L1/L2/persona_handoff.md) for the full mechanism.

## What You Get

- Recruiter setup flow: recruiter email, role title, focus areas, and a selectable panel of interviewer personas with per-persona minute budgets
- Candidate flow: mic check (with name capture) → live voice call → timer-driven auto-switch/auto-end across the panel → feedback report generation → an optional spoken debrief with the panel (candidate can talk through their feedback out loud, or skip straight to the written report) → instant feedback report, plus a detailed report emailed to the recruiter. The interview link is one-time-use — it's blocked once a report exists for the session.
- RTC audio plus RTM transcript and state events
- Server routes for token generation, agent invite/stop, session storage, and report generation
- [`AgentVisualizer`](https://agoraio-conversational-ai.github.io/agent-uikit/) for agent state and a built-in transcript panel for live turns, with persona-switch dividers
- Per-stage latency header driven by `AGENT_METRICS`
- Agora-managed default STT, LLM, and TTS configuration, with a distinct voice per persona

## How It Works

1. A recruiter submits the setup form; `POST /api/session` creates the session and returns a candidate link.
2. The candidate opens the link, passes a mic check, and the browser requests an RTC + RTM token from `/api/generate-agora-token`.
3. The backend invites an Agora cloud agent for the first persona with `/api/invite-agent`.
4. The browser joins the channel and publishes mic audio.
5. The client receives transcript, agent state, and `AGENT_METRICS` (per-stage latency) events over RTM.
6. Each persona has a recruiter-configured time budget; when it runs out, the panel auto-advances — the current agent session stops, a new one starts for the next persona with the prior conversation summarized into its prompt, and the RTC/RTM connection is untouched throughout. When the last persona's time also runs out, the interview ends automatically (the candidate can also end early at any time via "End conversation").
7. On end, the client calls `/api/stop-conversation` and posts the full transcript (plus the candidate's name from the mic check) to `/api/session/[id]/report` — the RTC/RTM connection stays alive so the candidate can optionally continue into a debrief. Once the report is ready, the candidate chooses "Talk to the panel about it" or "Skip to my written report."
8. If the candidate talks to the panel: `/api/invite-agent` starts one more agent session (same channel/UID) whose prompt is built from the just-generated report (never the recruiter-only hiring score), and the candidate can ask questions about their feedback out loud until they click "I'm Done" or a silent 4-minute safety cap ends the debrief.
9. Either way, the client then logs out RTM, unmounts the call view so Agora React hooks clean up RTC publish/join and the local microphone track, and shows the generated feedback report — emailing the same report to the recruiter on the first report for the session. Clicking "Done" on the report screen attempts to close the tab rather than restarting the flow, since the link is now one-time-use.

## Optional BYOK

The base `.env.local` contract requires Agora and Postgres credentials. If you are migrating from a supported provider, uncomment the matching snippet in [`app/api/invite-agent/route.ts`](app/api/invite-agent/route.ts) and add its variables to your local environment.

```bash
# Deepgram STT
NEXT_DEEPGRAM_API_KEY=...

# OpenAI-compatible LLM (also used for LLM-generated feedback reports)
NEXT_LLM_URL=https://api.openai.com/v1/chat/completions
NEXT_LLM_API_KEY=...

# ElevenLabs TTS
NEXT_ELEVENLABS_API_KEY=...
NEXT_ELEVENLABS_VOICE_ID=...
```

## Repo Map

- `app/api/generate-agora-token/route.ts` — issues RTC + RTM tokens
- `app/api/invite-agent/route.ts` — starts the agent session, per-persona prompt/voice, `handoff_log` write; also starts the post-interview debrief agent (`debrief: true`)

- `app/api/session/route.ts` — recruiter creates a session
- `app/api/session/[id]/route.ts` — loads a session for the candidate flow
- `app/api/session/[id]/report/route.ts` — generates and persists the feedback report
- `components/SetupScreen.tsx` — recruiter setup form
- `components/MicCheck.tsx` — pre-join mic check
- `components/InterviewSession.tsx` — candidate flow orchestrator (bootstrap, switch, report, debrief offer/start/end)
- `components/ConversationComponent.tsx` — RTC client, transcript state, `AGENT_METRICS`, mic release
- `components/PersonaSwitcher.tsx` — read-only mid-call panel status with a live countdown
- `components/DebriefCall.tsx` — post-interview spoken debrief call (join/converse/end, no persona timeline)
- `components/InterviewReport.tsx` — end-of-call feedback report UI
- `components/QuickstartConversationLayout.tsx` — in-call header, transcript rail, controls dock
- `components/QuickstartPipelineMetrics.tsx` — per-stage latency chips in the header
- `components/QuickstartTranscriptPanel.tsx` — live transcript rail with persona-switch dividers
- `lib/personas.ts` — persona definitions, prompt/greeting builders, and the debrief prompt/greeting/voice builders
- `lib/report.ts` — feedback report generation (LLM + heuristic fallback)
- `lib/mailer.ts` — recruiter report email delivery (Gmail SMTP, best-effort)
- `lib/conversation.ts` — transcript normalization, visualizer state mapping, persona attribution
- `lib/db/schema.ts` — `sessions` / `candidateContext` / `reports` / `events` tables
- `AGENTS.md` — primary agent-facing guide

## Troubleshooting

- **Agent does not join or transcripts are missing:** run `agora project doctor --deep`.
- **`pnpm run doctor` fails:** run `agora project env write .env.local`, then retry.
- **Manual clone / env values:** `agora project use <your-project>` then `agora project env write .env.local`.
- **Every `/api/session*` route 500s:** check `DATABASE_URL` is set and `pnpm run db:push` has been run against it.
- **RTM login fails:** keep [`app/api/generate-agora-token/route.ts`](app/api/generate-agora-token/route.ts) on `RtcTokenBuilder.buildTokenWithRtm` — RTC-only tokens will not satisfy `rtm.login`.
- **Transcript speakers inverted:** check the `uid === "0"` remap in [`components/ConversationComponent.tsx`](components/ConversationComponent.tsx).
- **Agent never appears in channel:** ensure the fixed agent UID in [`lib/agora.ts`](lib/agora.ts) is used by both the client and invite route, and is never varied per persona.
- **New persona repeats questions already asked:** ensure `session_id` and `fromPersona` are included on the switch request to `/api/invite-agent` — see [docs/ai/L1/L2/persona_handoff.md](docs/ai/L1/L2/persona_handoff.md).
